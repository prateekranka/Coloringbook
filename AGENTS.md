# AGENTS.md — Operating manual for AI coding agents

This file is for AI coding agents (Claude Code, Cursor, Codex, etc.) working in
the Gouache (formerly ColorFlow) repo. Humans should read `CLAUDE.md` for the architectural
narrative; this file is the short, imperative "how to get things done" guide.

If `CLAUDE.md` and this file disagree, **this file wins for workflow**;
`CLAUDE.md` wins for architecture and invariants.

## 2. Daily commands

Everything lives behind `./dev`. Never invent your own xcodebuild incantation
— the script handles simulator resolution, project regeneration, and arg wiring.

| Want to…                           | Run                                |
|------------------------------------|------------------------------------|
| Regenerate `ColorFlow.xcodeproj`   | `./dev gen`                        |
| Build for simulator                | `./dev build`                      |
| Run unit tests                     | `./dev test`                       |
| Run UI tests                       | `./dev uitest`                     |
| Run everything                     | `./dev all`                        |
| Open in Xcode                      | `./dev open`                       |
| See available simulators           | `./dev simlist`                    |
| Target a specific simulator        | `COLORFLOW_SIM="iPad (11th gen)" ./dev test` |

`./dev` auto-detects a booted iPad simulator, otherwise falls back to the
newest installed iPad runtime. **Never hardcode a UDID in scripts or tests.**

## 3. Template pipeline

Adding or updating coloring templates is a five-stage process. Run the whole
thing with one command:

```sh
# Put AI-generated PNGs in pipeline_work/01_rasters/
Scripts/pipeline/run.sh --rasters pipeline_work/01_rasters
```

This will:
1. Vectorize PNGs → raw SVGs (VTracer)
2. Post-process (transforms, IDs, closed paths)
3. Validate + split into `pass/` and `cleanup/`
4. Regenerate `ColorFlow/Resources/templates.json`
5. Copy passing SVGs into `ColorFlow/Resources/Templates/`

Then: `./dev gen && ./dev test && git diff ColorFlow/Resources/`.

For the full manual process, see `Scripts/pipeline/README.md`. For SVG
authoring rules (no arcs, closed paths, viewBox required), see
`docs/contributors/svg-cleanup-brief.md`.

## 4. Non-negotiable invariants

Do not change these without an explicit discussion in the PR description.

- **iPad only.** `TARGETED_DEVICE_FAMILY: "2"`. Do not add iPhone layouts,
  size-class branches for iPhone, or `@EnvironmentObject`-style code that
  assumes phone idioms.
- **Dark theme only.** Root view forces `.preferredColorScheme(.dark)`. Do
  not read `@Environment(\.colorScheme)` to branch behavior.
- **ViewModels are `@Observable` + `@MainActor`.** Do not reintroduce
  `ObservableObject` / `@Published` / `@StateObject` / `@EnvironmentObject`.
  Use `@State` for ownership, `@Environment(Type.self)` for injection,
  `@Bindable` when you need to derive bindings from an injected value.
- **`StorageService` I/O is serialized via a private `DispatchQueue`.**
  Do not call index-mutating methods from multiple tasks without going
  through the existing public API.
- **`SVGParser` is strict.** Arcs (`A`/`a` commands) and non-translate
  transforms are not supported. Pre-process SVGs upstream.
- **`project.yml` is the source of truth.** Never hand-edit
  `ColorFlow.xcodeproj/*`. After changing `project.yml`, run `./dev gen`.
- **Bundle ID and signing team in `project.yml` are baked.** Override
  locally for your device; do not commit changes to
  `PRODUCT_BUNDLE_IDENTIFIER` or `DEVELOPMENT_TEAM`.
- **Tool limitations.** Use `./dev` for build, test, simulator selection,
  and project-regeneration workflows.

## 5. Conventions for agent-authored changes

**Do:**
- Make one logical change per PR. If you're touching the canvas pipeline
  *and* refactoring persistence, split it.
- Add or update unit tests when changing a `Service` or `ViewModel`.
- Run `./dev test` before reporting "done."
- When modifying templates, re-run the pipeline + re-generate the project.
- Prefer structured concurrency (`Task {}`, `Task.detached`) over
  `DispatchQueue.global` + `withCheckedContinuation`.

**Don't:**
- Introduce new third-party dependencies without discussion. SVGKit is
  currently stubbed (`OTHER_LDFLAGS: ""`) — do not link it.
- Add comments describing *what* the code does. If the code isn't clear,
  rename things. Only comment on *why* when non-obvious.
- Create documentation files unless explicitly asked.
- Re-introduce hardcoded simulator UDIDs in shell scripts or CI.
- Bypass `StorageService` to read/write `projects.json` directly.

## 6. Pre-commit checklist

Before handing a change off to a human reviewer:

- [ ] `./dev gen` runs cleanly if `project.yml` changed
- [ ] `./dev test` passes
- [ ] No new `@Published`, `ObservableObject`, `@StateObject`, or
      `@EnvironmentObject` introduced
- [ ] No new `DispatchQueue.global` + `withCheckedContinuation` patterns
- [ ] `git status` is clean except for the files this change intended to
      modify (watch for stray `ColorFlow/.build/`, `.DS_Store`, IDE scratch)
- [ ] If templates changed: `python3 Scripts/validate_template_svg.py
      ColorFlow/Resources/Templates/` passes

## 7. Known gotchas

- **`@AppStorage` doesn't work inside `@Observable` classes.** Use
  `UserDefaults.standard` directly. `CanvasViewModel.recentColors` is the
  existing pattern — follow it.
- **`.environmentObject` is gone.** Use `.environment(myObservable)` and
  read with `@Environment(MyType.self)`. For bindings derived from an
  injected `@Observable`, wrap with `Bindable(viewModel).prop` or declare
  the property as `@Bindable` inside the view.
- **SVGs must be in the flat bundle root.** The `preBuildScript` in
  `project.yml` copies them from `ColorFlow/Resources/Templates/` to the
  bundle root. `Template.svgURL` tries both locations.
- **`templates.json` has a fallback.** If the bundled JSON fails to load,
  `Template.bundledTemplates` (a hardcoded array) is used. Keep them in
  sync when adding templates, or accept the JSON as canonical.
- **Prefer `./dev` over raw build commands.** If a direct command behaves
  differently from `./dev`, debug the wrapper first.
